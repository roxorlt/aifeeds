# ICP 备案与 ai-feeds.cc 国内合规线讨论备忘录

> 2026-05-04 ~ 2026-05-10 期间，作为不懂代码的 PM 与 Claude（Opus 4.7）的完整对话记录。

> **主线**：ai-feeds 项目主站在 Cloudflare 上，要接入微信登录 / 腾讯云短信 / 微信分享，这些都需要 ICP 备案。讨论如何在不动 CF 全球版（ai-feeds.com）的前提下，最小成本完成国内合规线（ai-feeds.cc）。

> - ai-feeds.cc 已部署 5 个静态合规页（首页 / 隐私政策 / 服务条款 / 联系我们 / style.css），通过 SSH 远程部署

## Q1：ai-feeds 接入微信登录 / 腾讯云短信 / 微信分享，前后端都在 CF 上，能不动 CF 直接备案吗？

**结论**：不能。备案有两条硬性规则：
1. 服务器必须在中国大陆境内
2. 备案后 24 小时内域名必须解析到该境内服务器，工信部 / 接入商会做拨查

CF 在境外节点，**完全无法用来备案**。这是技术上的死路。

### 三种方案对比

**方案 A：单独买备案专用域名**（最推荐 ⭐）
- ai-feeds.com 完全保留在 CF 不动
- 单独买 .cn / .cc / .com.cn，备案这个新域名解析到腾讯云轻量服务器
- 微信登录回调、短信回调、微信分享 JS 安全域名 → 都用这个备案域名
- 主站逻辑（Worker、Pages、D1、R2）继续在 ai-feeds.com 上跑

**优点**：
- ✅ Claude Code 现有部署流程**完全不变**（CF API token 照常用）
- ✅ CF 全球加速优势保留
- ✅ 工程量最小
- ✅ 月成本 ~25 元（轻量服务器） + ~50/年（域名）

**方案 B**：transfer ai-feeds.com 到腾讯云做备案 + DNS 智能解析（国内→腾讯云、国外→CF）
- ❌ 工程量翻倍：CF Worker 要在腾讯云上重写一份
- ❌ 多套部署同步维护
- ❌ DNS 从 CF 搬走，CF 边缘缓存等优化能力打折

**方案 C**：完全迁到腾讯云
- ❌ 抛弃 CF 边缘性能优势
- ❌ Worker → 腾讯云 SCF / EdgeOne，D1 → MySQL/PG，R2 → COS — 全部重写
- ❌ 失去全球可访问性这个核心卖点

### 关键概念澄清

「域名注册商 / DNS 解析 / 托管服务」是三件**独立**的事：
| 概念 | Claude Code 部署用的是哪个 |
|------|--------------------|
| 域名注册商（谁卖给你域名） | 不相关 |
| DNS 解析（域名指向哪台服务器） | 相关 |
| 托管/部署（实际跑代码的地方） | 相关（Claude Code 用 CF API） |

→ **域名 transfer 不影响 Claude Code 部署**，但备案要求"备案域名必须解析到境内"，所以方案 B 下 DNS 必须从 CF 搬走。

## Q2：短信签名【】里的内容必须是企业名吗？能用产品名吗？

**结论**：企业主体下，签名来源可以是以下任一（**只要能在备案 / 商标 / 公众号 / 小程序上呈现产品名，就能用产品名做签名**）：

| 签名来源 | 需要的证明 |
|---------|----------|
| 公司全称 / 简称 | 营业执照 |
| **已备案的网站名称** | ICP 备案截图 |
| 已注册商标名称 | 商标注册证 |
| 已上线公众号 / 小程序名称 | 首页截图 |

**🔑 隐藏策略**：备案时填的"网站名称"会成为后续短信签名的合法来源。备案时就把"网站名称"填成想要的产品中文名，备案号下来后直接用，**不需要额外注册商标**。

**签名格式硬性要求**：
- 长度 2-12 字
- **必须含中文**（纯英文不行）
- 例：【AI看板】✅ ｜【AI Feeds】❌

## Q3：方案 A 下工信部拨查是查 ai-feeds.cn 还是 ai-feeds.com？com 不写 ICP 信息会被罚吗？

**拨查对象 = 备案域名**（ai-feeds.cn）：
- 拨查会访问 https://aifeeds.cn 看是否能正常打开
- 看页面内容是否和备案登记的"网站名称、简介"匹配
- 看 footer 是否显示备案号 + 链接 beian.miit.gov.cn
- **ai-feeds.com 完全不在拨查范围**

**ai-feeds.com 不写 ICP 信息**：
- 法律层面：境外服务器不要求 ICP 号，**完全没问题**
- 实操层面：除非要在国内做付费投放 / 上架国内 App 商店 / 被举报，否则不会被追究

**最务实做法**：
- ai-feeds.com footer 不加 ICP（无法备案，不要求）
- 国内业务（登录 / 分享 / 短信）全部通过 aifeeds.cn 处理

## Q4：aifeeds.cn 这个备案站要放什么内容？

**必须满足**：
1. 内容要和备案登记的"网站名称、简介"对得上
2. 不能是空壳页 / 跳转页 / 维护中页
3. 必须有 footer：ICP 备案号 + 链接到 beian.miit.gov.cn + 公安备案号（30 天内办）+ 联系邮箱

**推荐结构（最少 5 个页面）**：
```
aifeeds.cc/
├─ /                  首页（产品介绍，与备案简介对应）
├─ /privacy.html      隐私政策（国内业务硬性要求）
├─ /terms.html        服务条款
├─ /contact.html      联系我们（邮箱必须有）
├─ /style.css         共用样式
└─ /MP_verify_xxx.txt 微信公众号校验文件（待申请）
```

**不能放**：
- ❌ 全英文页面
- ❌ "Coming Soon" 单页
- ❌ 直接 redirect 到 ai-feeds.com
- ❌ 加密货币 / 跨境支付 / 博彩
- ❌ 不可控 UGC

## Q5：分享功能要重新设计？用户在 com 上发起，校验文件在 cn 上放着，跑得通吗？最后一步重定向会不会被微信拦？

**结论**：能跑通，是行业标配的「Login Bridge / Share Bridge」模式。但**不能用立即重定向**，要用「预览页 + 用户主动点击」避免触发微信「诱导跳转」风控。

### 微信生态对域名的硬性要求

| 微信能力 | 域名要求 | 校验文件 |
|---------|---------|---------|
| 微信扫码登录（Web） | 「授权回调域名」必须已备案 | 不需要文件 |
| 公众号网页授权（H5 登录） | 「网页授权域名」必须已备案 | `MP_verify_xxx.txt` 放根目录 |
| 微信 JS-SDK（分享、支付） | 「JS 接口安全域名」必须已备案 | `MP_verify_xxx.txt` |

→ 这些校验文件 + 回调域名**只能配 aifeeds.cc**，ai-feeds.com 无法配（没备案）。

### 分享有两种模式（不要混淆）

**模式 1：图片海报分享**（最常见，**不依赖 JS-SDK**）
- 后端用 Canvas / Satori 合成海报图片，二维码指向 aifeeds.cc/s/xxx
- 海报生成可在 CF Worker 上做，**不需要走 aifeeds.cc**
- 用户长按保存图片 → 自己打开微信发送
- 完全不需要 JS-SDK

**模式 2：微信原生分享卡片**（需要 JS-SDK，**只在微信内置浏览器有效**）
- 用 wx.updateAppMessageShareData 自定义卡片
- 当前页面域名必须在「JS 接口安全域名」里（aifeeds.cc）
- 后端要计算 signature

### 修正后的分享流程

**发起分享**（用户在 ai-feeds.com 上）：
1. 点击"生成海报" → CF Worker 生成图片，二维码指向 aifeeds.cc/s/abc12345
2. 用户保存海报到相册 → 自己发到微信
- ✅ 全程在 CF 上完成，aifeeds.cc 不参与生成

**接收方扫码回流**：
1. 微信扫码 → 微信浏览器打开 aifeeds.cc/s/abc12345
2. aifeeds.cc 服务端调 ai-feeds.com/api/share/resolve?token=xxx 拿到内容
3. **渲染预览页 + "查看完整内容"按钮**（不要立即重定向！）
4. 用户主动点击 → location.href = ai-feeds.com/t/xxx

### 为什么不能立即重定向

微信对"诱导跳转"的判定会拦：
- ❌ `<script>location.href = 'ai-feeds.com/...'</script>`（风险）
- ❌ `<meta http-equiv="refresh" ...>`（风险）
- ✅ `<a href="...">查看完整内容</a>`（安全）

用户主动点击触发的跳转完全不会被拦。预览页还能：
- 即使用户没点跳转也获取到核心信息（提升留存）
- aifeeds.cc 有真实内容，备案核查不扣分
- 预览页可加 JS-SDK 让用户「在微信里二次分享」

## Q6：微信开放平台有 PC OpenSDK 直接拉起 PC 微信分享，是不是不需要 aifeeds.cc 了？

**抓了 https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_PC_APIs/share.html 文档后的结论**：PC OpenSDK 改变了 PC 端的分享体验（一键拉起 PC 微信），但**没有改变备案要求**。

PC OpenSDK 的硬性前提：
1. 网站应用通过审核（300 元/年企业认证）
2. **登记业务域名**（必须备案）
3. 申请到「发送给朋友」+「分享到朋友圈」权限
4. 调用时**当前页面必须在已登记业务域名下**
5. 仅支持微信 4.1.0+ for Mac/Windows，目前**灰度测试中**

→ 业务域名 = 必须备案，所以**只能配 aifeeds.cc**，ai-feeds.com 不能直接用。

### 三路径分发（按用户场景）

| 场景 | 用什么 | 体验 |
|------|-------|------|
| PC 浏览器 | PC OpenSDK 一键拉起 | ⭐⭐⭐⭐⭐ |
| 移动浏览器 | 海报 + 手动分享 | ⭐⭐⭐ |
| 微信内浏览器 | JS-SDK 自定义卡片 | ⭐⭐⭐⭐ |

**所有路径都依赖 aifeeds.cc 这个备案域名**。备案不能省，但 PC OpenSDK 当**渐进增强**用（PC 端体验飞跃）。

## Q7：腾讯云买域名搭售的轻量对象存储 / SSL 证书 / CVM 云硬盘，要不要一起买？

**全部不必买**：

1. **轻量对象存储 ❌**：已有 CF R2，且微信只要求"公网可访问 URL"不要求资源在业务域名下，搭售套餐通常是大容量年包，浪费
2. **SSL 证书单域名 ❌**：腾讯云**自带免费 DV 证书**，1 年有效到期免费续签，功能和付费证书完全一样（普通 SaaS 不需要 OV/EV）
3. **CVM 云硬盘 ❌**：你买的是**轻量应用服务器（Lighthouse）**，CVM 云硬盘**只能挂载到 CVM**，挂不到 Lighthouse —— 买了用不上，纯交叉销售套路

## Q8：ai-feeds.cc 这种 .cc 后缀能在中国备案吗？

**初期判断**：高风险。`.cc` 是 Cocos (Keeling) Islands 国家顶级域，2017 之前能备案，2018 工信部收紧后基本被踢出白名单。腾讯云 / 阿里云**支持注册 .cc 但不支持备案**是常见坑。

**实际验证**：用户走到了备案最后一步，腾讯云系统接受了 .cc 域名 — 说明这个限制可能放宽了，或者用户已经过了系统校验那一关。继续推进。

**同类潜在问题域名（备案前要核实）**：`.tv` / `.me` / `.io` / `.app` / `.ai` / `.co` / `.xyz`

## Q9：腾讯云买好了 .cc 域名 + 轻量服务器（已装宝塔）+ SSL + COS，下一步怎么做？

### Step 1：DNS 解析配置

腾讯云控制台 → 域名 → DNSPod → 加 2 条 A 记录（必须）：

| 主机记录 | 记录类型 | 记录值 | TTL |
|---------|---------|--------|-----|
| `@` | A | 82.156.0.68 | 600 |
| `www` | A | 82.156.0.68 | 600 |

> 备案审核同时拨查 ai-feeds.cc 和 www.ai-feeds.cc，缺一条核验失败。
> 不要加 CNAME 到 ai-feeds.com，不要配 MX，不要开 CDN（备案前禁用）。

### Step 2：拿宝塔面板访问信息

```bash
sudo /etc/init.d/bt default
```

输出包含：
- 外网面板地址：http://82.156.0.68:8888/tencentcloud
- 用户名 / 初始密码

### Step 3：腾讯云轻量服务器防火墙

加规则（注意：腾讯云轻量服务器有自己的云防火墙，独立于操作系统）：
- TCP 8888（宝塔面板，配置完后可关）
- TCP 80（HTTP）
- TCP 443（HTTPS）
- TCP 22（SSH）

### Step 4：宝塔后台加站点

新版宝塔的「网站」菜单，**纯静态选「HTML项目」**（不是「添加站点」）：
- 域名填两行：ai-feeds.cc / www.ai-feeds.cc
- 根目录默认 /www/wwwroot/ai-feeds.cc
- PHP 版本：纯静态
- 不创建数据库 / FTP / SSL（暂时）

## Q10：从外网访问 ai-feeds.cc 报 ERR_EMPTY_RESPONSE 是什么原因？

**诊断脚本**（在服务器上跑）：
```bash
echo "===== 1) DNS resolves to ====="; getent hosts www.ai-feeds.cc ai-feeds.cc
echo "===== 2) Nginx loaded sites ====="; sudo nginx -T 2>/dev/null | grep -E '^\s*(server_name|listen|return)' | head -40
echo "===== 3) Local Host header test (apex) ====="; curl -sIv --max-time 5 -H "Host: ai-feeds.cc" http://127.0.0.1/ 2>&1 | head -15
echo "===== 4) Local Host header test (www) ====="; curl -sIv --max-time 5 -H "Host: www.ai-feeds.cc" http://127.0.0.1/ 2>&1 | head -15
echo "===== 5) External IP test ====="; curl -sIv --max-time 5 http://82.156.0.68/ 2>&1 | head -15
echo "===== 6) Site folder ====="; ls -la /www/wwwroot/ai-feeds.cc/
echo "===== 7) Nginx error log ====="; sudo tail -15 /www/wwwlogs/nginx_error.log 2>/dev/null
```

**诊断结果定位**：本地 curl 走 Host header 返回 200 OK ✅；但外部 IP 直连 80 端口超时 ❌ → **腾讯云云防火墙没开 80**。

→ 修复：腾讯云控制台 → 轻量服务器 → 防火墙 → 加规则 TCP 80 允许。

## Q11：终端粘贴大段 heredoc 卡死，能给我 SSH 密钥让 Claude 直接进吗？

腾讯云 webshell 对粘贴大量内容的处理不稳，触发 heredoc 续行时容易卡。改走 SSH 远程操作。

### 临时密钥流程

**在服务器跑（生成临时密钥对）**：
```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/claude_temp -N "" -q -C "claude-temp"
cat ~/.ssh/claude_temp.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
echo "=========== 私钥开始 ==========="
cat ~/.ssh/claude_temp
echo "=========== 私钥结束 ==========="
```

**用户把私钥（包含 BEGIN/END 行）发给 Claude** → Claude 保存到本地 `~/.ssh/aifeeds_temp` (chmod 600) → SSH 连接：

```bash
ssh -i ~/.ssh/aifeeds_temp -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o LogLevel=ERROR lighthouse@82.156.0.68
```

**事后撤销**（备案过审 + SSL 配好后）：
```bash
rm ~/.ssh/claude_temp ~/.ssh/claude_temp.pub
sed -i '/claude-temp/d' ~/.ssh/authorized_keys
```

### 部署 5 个静态文件的实际流程

1. 本地用 Write 工具创建 5 个文件到 `/tmp/aifeeds-staging/`（style.css + 4 个 HTML）
2. `scp -i ~/.ssh/aifeeds_temp /tmp/aifeeds-staging/*.{html,css} lighthouse@82.156.0.68:/tmp/`
3. `ssh ... 'sudo cp /tmp/*.html /tmp/style.css /www/wwwroot/ai-feeds.cc/'`
4. `sudo chown www:www /www/wwwroot/ai-feeds.cc/{index,privacy,terms,contact}.html /www/wwwroot/ai-feeds.cc/style.css`（**要精确指定文件**，不要 -R 整个目录，否则会卡在宝塔的 .user.ini 上 immutable 报错）
5. `sudo chmod 644 ...`
6. 远程 curl 验证 5 个 URL 都返回 200 OK

## 教训 & 心得

1. **域名注册商支持注册 ≠ 支持备案**。`.cc` `.tv` `.me` `.io` 这些后缀很多境内接入商不能备案，买之前先确认。
2. **腾讯云轻量服务器的"防火墙"是云上的安全组，独立于操作系统的 firewalld**。8888 / 80 / 443 / 22 都要在云防火墙开，操作系统层面再 OK 也没用。
3. **新版宝塔的「添加站点」改成了按项目类型拆开**——纯静态选「HTML项目」，不是老版的"纯静态站点"。
4. **腾讯云 webshell 粘贴大段 heredoc 不稳**——超过 50 行就容易卡死。要么用 SCP 上传文件，要么用 SSH 远程执行。
5. **宝塔自动给站点的 .user.ini 加了 chattr +i**（immutable），`chown -R` 会报错。要精确指定要 chown 的文件，跳过 .user.ini 和 .htaccess。
6. **微信开放平台的"业务域名" / "JS 接口安全域名" / "网页授权域名" 三个名字不同但本质都要求已备案**。
7. **微信对"诱导跳转"的判定**会触发风控（黄条警告 / 域名被屏蔽）。备案站到主站的跳转必须用「预览页 + 用户主动点击」，不能用 JS 立即重定向 / meta refresh。
8. **腾讯云搭售套餐基本都是坑**——免费 SSL 完全够用、CVM 云硬盘挂不到 Lighthouse、对象存储按量计费比包年便宜。配置时全部取消勾选。
9. **备案预审电话**：网站名称会被建议调整（避免敏感词、避免与已有备案重名）。预审员会明确告知「网页内容是否需要改成最终备案名」——这次的反馈是「不需要，保持现状即可」。
10. **品牌名分层管理**：备案主体名 / 网页展示名 / 全球版品牌名可以不一致，分场景使用。
