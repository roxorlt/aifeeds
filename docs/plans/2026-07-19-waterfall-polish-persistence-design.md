# 瀑布流精修与设备持久化设计

## 背景

生产瀑布流已经恢复双列/多列布局、封面展示和紧凑间距，但仍有五个可见问题：

1. 封面加载意图不稳定：SSR 只会为落在前几个 DOM 位置的图片生成 preload；前几个卡片无图时，真正首张图片仍可能懒加载。
2. 瀑布流没有提前连接 `api.ai-feeds.com`，首张跨域图片需要临时完成 DNS、TCP 和 TLS。
3. 香港 VPS `/img` 缓存键只包含 URL，不区分浏览器接受的 AVIF、WebP、JPEG，导致浏览器可能命中更大的 JPEG 变体。
4. Service Worker v4 对所有 SPA 导航返回缓存的经典版 `/`，绕过服务端的 `aifeeds_view` Cookie 选择。
5. 瀑布流独立 Shell 没有经典版的移动端“上推收起、下拉展示”顶栏逻辑；卡片视觉仍停留在平面线框状态。

## 设计结论

采用“精致内容社区卡片”方向。保留小红书式双列/多列浏览密度，但不复制其视觉：

- 封面是第一视觉层，图片卡标题控制在 2–3 行；摘要只保留必要信息。
- 无封面卡以更完整的文字层级补足信息量。
- 来源图标、来源名称、次级身份和发布时间形成紧凑身份区。
- 热度指标使用图标化的轻量底栏，不与标题争夺注意力。
- 卡片使用 12px 圆角、克制阴影、细边框和短距离 hover 抬升；移动端不使用 hover 效果。
- 保持固定列宽、独立卡片和 8px 瀑布间距，不增加分类 Tab、侧栏或顶部宣传文案。

## 交互

### 移动顶栏

- 仅小于 768px 启用。
- 距离页面顶部 50px 内始终显示。
- 向上滚动时按 1:1 距离把 54px 顶栏移出视口；向下滚动时按相同距离拉回。
- 使用 `transform`，不触发布局；PC 始终保持 sticky。
- `prefers-reduced-motion: reduce` 时顶栏始终显示。

### 视图持久化

- `aifeeds_view` 的 180 天 Secure Cookie 继续作为服务端 SSR 的唯一权威来源。
- Service Worker 不再拦截 `/` 的导航；首页始终交给服务器根据 Cookie 或显式 `?view=` 选择视图。
- 哈希静态资源仍使用 Cache API；深链保留壳回退能力。
- 更新 Service Worker 版本以清理旧壳缓存。

## 图片加载

- 根据“有图卡片的顺序”分配媒体优先级，而不是根据全部卡片序号：
  - 第一张有图卡片：`eager + high`
  - 第二张有图卡片：`eager + auto`
  - 其余：`lazy + auto`
- 瀑布流 HTML 对 API 图片域增加 `preconnect` 和 `dns-prefetch`。
- 有 400/800 WebP 持久化变体时输出 `srcset` 和列宽感知的 `sizes`；否则安全回退到现有图片 URL。
- 保留明确宽高，避免图片加载导致布局位移。

## 生产图片缓存

Nginx 将浏览器 `Accept` 归一为 `avif`、`webp`、`original` 三个有限桶，并把桶名加入 `/img` 的缓存键。变更后只清 `/img` 缓存，不清 HTML 或其他静态资源；验证同一 URL 在不同 Accept 下得到正确 `Content-Type`，并确认 MISS → HIT。

## 验收

- 刷新和重新打开受 Service Worker 控制的浏览器后，瀑布流选择仍保持。
- 移动 Chromium 与 WebKit 中，顶栏上推收起、下拉展示；PC 不收起；减弱动效模式始终显示。
- 首张实际封面为 `eager/high`，第二张为 `eager/auto`，HTML 包含图片域预连接。
- 双端维持 2/3/4/5/6 列、最大纵向视觉间距小于 17px、CLS 不高于 0.1。
- 卡片无横向溢出，键盘焦点可见，封面失败后卡片与瀑布重新收紧。
- 生产 `/img` 对支持 AVIF/WebP 的请求不再被旧 JPEG 缓存污染。
