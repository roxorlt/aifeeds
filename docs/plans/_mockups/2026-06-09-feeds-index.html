本次已定决策（mockup 照此画，无需再确认）

★★★ 来自 §10 / §13
  • 合并单频道「官方新闻」（D7）：顶部只 +1 个 chip（filter blog,podcast），两源同列按 published_at 倒序混排；底层仍是 2 source_type + 2 workflow + 2 卡片样式（前端合并、数据模型不合并）。
  • blog 卡 = YouTube 家族（范本 HfPaperCard）：可选满宽 16:9 封面 + 标题中译 + ELI25 摘要 + [logo] 厂商 · N 天前 · 约 N 分钟 [分类]，无互动数行。
  • podcast 卡 = TweetCard 家族：左 72×72 方形圆角封面 + 封面叠加 play 三角（复用 PhCard 的 M8 5v14l11-7z）+ 节目名/单集标题/shownotes 摘要 + 单集时长，无互动数行。
  • 翻译走 ELI25（像跟聪明的 25 岁年轻人解释）；外文源抽屉提供译/原 toggle，中文源不出现。
  • podcast 音频：MVP 用原生 <audio controls>，src = 原始 enclosure 直链不迁 R2（大陆访问可能较慢，诚实告知 + 原平台兜底）。
  • 海报来源 chip 配色（§10.4）：blog = #bae6fd（sky 冷蓝），podcast = #f2c4ee（orchid 洋兰紫粉）；均不撞 X/GH/PH/ClawHub/HF/HDX 现有源色。
  • 零 emoji + 全 neutral token：UI chrome 一律 lucide 风 SVG；灰阶 + 链接 sky-600 + 危险 rose-600，品牌橙只活在 logo；feed 卡 border-b 分隔，无 shadow / rounded / bg-white。

待你挑的变体（确认后才进 Phase 1 编码）

★ 需拍板
  • blog 封面布局（变体对比页 A）：有图时默认走 ① 满宽 16:9（推荐，对齐图文家族）还是 ② 右侧 112×84 缩略图？③ 无封面纯文字是无图必备兜底，三态都要实现。
  • publisher logo（D9，变体对比页 B）：主用 ① BE 迁 R2 的真实公司 logo（推荐）还是 ② 首字母 monogram 彩块？另一种作 fallback。
  • podcast「有文字稿」chip（变体对比页 C）：A 档单集是否保留这枚 chip 区分 B/C 档？
  • 频道命名：「官方新闻」是否合适？播客严格讲非「新闻」，可换「官方动态 / 厂商前线」等。
  • 海报来源 chip 文案：色已定（blog #bae6fd / podcast #f2c4ee），文字「厂商博客 / AI 播客」待定。

审查 agent 另发现 2 处需对齐：① AppBar chip —— kit 同时画了独立「Podcast」chip + 「官方新闻」，feed-mockup 只画「官方新闻」占 podcast 槽位；按 §10.5#3 / D7「占原 podcast 槽位、不再单列、只 +1」应以 feed-mockup 为准，建议 kit 对齐。② 抽屉头左键 —— drawer-blog 用关闭按钮（ico-close），drawer-podcast 与 kit 外壳用返回按钮（ico-back），建议统一。
