README 条件渲染规则：
  • 原文是中文（readme_lang = 'zh'）→ 不出 tab，直接出原文
  • 原文是其他语言（英文 / 日文 / 韩文 等）→ 出双 tab "English / 中文"，默认选原文
  • 语言判定：抓 README 后扫前 N 字符的 CJK 占比 ≥ 30% → 'zh'，否则 'en' / 'other'（启发式 + 0 LLM 成本）
  • 中文翻译 = enrich pipeline 异步任务，新建 readme_translated 字段；翻译时 README 中的 <img> 资源 URL 抽出 → 下载到 CF R2 → 重写到 markdown 落库（参考 xlist 现有 link_card 图片做法）

分享 / URL routing 设计

复用 X 推文 drawer 已实现的 /t/:id 模式（见 docs/plans/2026-04-30-dashboard-url-routing-design.md），GitHub repo 用对应路由。

URL 结构

  • /g/:owner/:repo — 单条 repo 详情（与 GitHub 自身 URL 同构）
  • /t/:id — X 推文（已上线，保持不动）
  • 未来：/p/:paper_id、/v/:video_id 等

用 source-prefixed slug 而非统一 /i/:source/:id，URL 更短更可读，分享回流时人眼能识别"这是个 GitHub 项目"。

深链行为（同 X 推文）

  • 应用内点卡片 → history.pushState('/g/:owner/:repo') → drawer 开
  • 关闭 drawer / ESC / 遮罩 → history.back() → 回 /
  • 冷启动深链 → replaceState('/') + pushState('/g/...') seed 历史栈
  • 后退键 → 回首页 feed（不退出站）

分享回流：被分享的 repo 强插到 feed 顶部

复用 d80a38f commit 的"被分享推文强插到 feed 顶部"机制：用户点击别人分享的链接进入 /g/:owner/:repo，drawer 打开后，关闭 drawer 时底层 GitHub 列里这条 repo 出现在最顶部（即使它已经过期不在当日 trending）。

  • Worker 端：GET /api/items/:source/:id 返回单条；GET /api/feed?source=github&pinned=:owner_repo 把 pinned id 排首位
  • 前端：从 /g/:owner/:repo 进入时，feed query 带 ?ref=share&pinned=...，对应卡显示一个不显眼的 "from share" 视觉锚点（参考 X 那条的实现）
  • 后续：上报 SDK 落 events 表，分享外链点击 → drawer 打开 → 强插 → 关闭后保留在 feed 顶部，回流路径完整
