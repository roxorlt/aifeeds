# G8 v12 responsive-image settle fix

G8 v12 proved two independent faults. A valid 400 px Blog WebP is selected on all mobile engines, but `sizes="96px"` makes the browser expose density-corrected `naturalWidth=96`; the Blog card then applies a 240 px source-quality threshold to that display-space value and removes the image. On desktop, legacy Product Hunt rows reference missing staging R2 objects. Their images fail and are removed by the existing fallback, but the performance gate can sample them during the few milliseconds before React unmounts them and incorrectly treat that transient node as a candidate regression.

Three approaches were considered: lower the Blog threshold to 96 px and ignore decode errors; add controlled Product Hunt seed data and keep the current sampling model; or preserve the 240 px source-quality rule by using matched variant metadata, while making the gate wait for the final visible DOM to converge. The third approach is selected. It keeps the product-quality rule, covers fallback originals, and tests the state users actually see without weakening exact assertions for owned X and Blog fixtures.

Implementation is intentionally narrow. A pure image-quality helper will use `currentSrc` to match a stored variant and evaluate its declared pixel dimensions, falling back to browser intrinsic dimensions when no variant matches. Only `BlogCard` adopts it. The remote media-settle helper will repeatedly re-query visible connected images until they decode, disappear through the app's error fallback, or reach the existing five-second ceiling. A still-connected broken image remains a hard failure. Timeout diagnostics expose only safe fields such as feed source, priority, and failure state; they do not emit arbitrary URLs. Tests must first reproduce both v12 failures, then prove the fixes while retaining the existing fail-closed timeout and exact owned-variant checks.
