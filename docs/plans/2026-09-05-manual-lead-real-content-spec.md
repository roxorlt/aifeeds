# 补录线索产出真实内容 · 设计规格（2026-09-05）

> **owner 定的需求**（原话要点）：
> 1. 有的补录能给链接，有的只有一句话线索。
> 2. 有链接：提取页面正文 → 走一轮 DeepSeek 分析这是什么新闻 → 走一轮搜索 → 正文与搜索结果一起交给 DeepSeek 生成 title 与口播词。无链接：只走搜索，搜索结果交给 DeepSeek 生成。
> 3. 抓取能力必须**前置验证**，不能到开发阶段再按测试结果调整。
> 4. 补录内容的 title / 口播词 / 字幕 / 小红书文案，文字质量与数量都要与非补录内容一致，注意提示词。
> 5. 超时可放宽到一两分钟，页面要交代当前在抓取还是搜索，避免困惑焦虑。
> 6. 「公开报道」分档：非推特链接算公开报道；推特内容不算公开报道，但正文仍可用，口播需注明「博主某某发文称」。主会话追加第三档并获 owner 认可：官方 X 账号（白名单）算第一方公告。

## 0. 前置能力验证结论（2026-09-05 实测，prod 网关）

**已验证可用，不再是未知数。** 这一节是需求第 3 点的答复，开发中不得再以「不确定能不能抓到」为由变更方案。

| 情况 | 实测结果 |
|---|---|
| 微信公众号文章 | 成功，6200 字，2.3s |
| X 推文 | 成功，走 ScrapeBadger 推文接口 |
| 境外文章页（openai.com/index/…） | 成功，20000 字，0.73s |
| 境外站经香港代理 | 0.3–0.4s（直连 The Verge 需 12s） |
| 境内站（news.cn / blogs.nvidia.cn） | 成功 |
| **ScrapeBadger 搜索（已付费在用）** | **可用**：中英文查询均返回真实结果，耗时 8–26s |
| 免密钥 DuckDuckGo 兜底 | **不可用**，每次返回反爬拦截页（HTTP 202 + anomaly），零结果 |

**不需要申请任何新密钥。** 搜索当前失效的两个原因都是本仓库的问题：
- **Bug**：`date` 为空字符串时构造时间对象抛 `Invalid time value`，keyed 搜索必挂（网关日志可见）。
- **预算过紧**：单家 4s / 总 12s，而 ScrapeBadger 搜索实际需 8–26s。

两者都必须在本次修掉。DuckDuckGo 兜底保留但降级为「最后手段」，不得作为主路径，也不得在文档或提示里宣称「无需密钥即可搜索」。

## 1. 目标流程

提交后**立刻返回**，加工在后台跑，卡片实时显示进度。

```
有链接：
  抓正文(/v1/plain-text) → DeepSeek 读懂是什么新闻并拟检索词 → 搜索 → 抓回结果正文
                                                                    ↓
  正文 + 搜索素材 → 分档加出处前缀 → 复用常规新闻的生成函数 → title_zh / ai_summary_zh
无链接：
  owner 那句话即检索词 → 搜索 → 抓回结果正文 → 同上
```

生成出来的 title 与 summary **就是候选的标题与摘要**（写进签名投影），不是事后附加。owner 那句话作为「这条新闻讲的是什么」的锚点约束生成不跑题，不再直接当成品。

**任何一步失败仍然入池**，退回用 owner 那句话当标题，并在卡片上标明。入池永不失败，这是 9/4 修复的核心，不得回退。

## 2. 素材分档与出处标注

取材结果自带来源类型与发布者，不需要新写判别。

| 档位 | 判定 | 算公开报道 | 交给生成函数前加的出处前缀 |
|---|---|---|---|
| A 媒体报道 / 厂商官方博客 | 非 x.com/twitter.com 的链接 | 是 | 无需前缀，正常陈述 |
| B 官方 X 账号 | x.com 且 handle 命中 `OFFICIAL_X_ACCOUNT_ACTORS`（15 个，见 `manual-news-leads.ts`） | 是（第一方公告） | `以下内容为 <Actor> 官方账号的公告：` |
| C 其他 X 用户 | 其余 x.com/twitter.com | 否（UGC） | `以下内容为 X 博主 @<handle> 的发文，非媒体报道：` |

**关键实现要求**：出处信息通过**素材文本前缀**传达，**不改动共享提示词**。这样常规新闻那条生成路径零风险。

**排序规则**：搜索召回混合结果时，A 档优先作主素材，B 档次之，C 档只作补充。绝不在有 A/B 档素材时拿 C 档当主料。

## 3. 复用常规新闻的生成能力（需求第 4 点）

**事实**（已勘察确认）：常规新闻的 `extra.title_zh` 与 `extra.ai_summary_zh` 由 `classifyAndTranslateForFeeds`（`worker/src/feeds/classify-translate.ts:503`）一次 `deepseek-v4-flash` 调用同时产出；口播词、字幕、小红书文案、公众号标题、话题标签**全部从这两个字段派生**，面板侧没有第二套独立生成器。所以这两个字段用同一套提示词生成，其余各处质量自动一致。

**要做的重构**：把 `classify-translate.ts` 里的纯生成逻辑抽出并导出：

```ts
export async function generateFeedEnrichment(env, input: {
  title: string; excerpt: string; sourceCompany: string; lang: FeedLang; kind: FeedKind;
}): Promise<EnrichResult | null>
```

`classifyAndTranslateForFeeds` 改为「读库 → 调 `generateFeedEnrichment` → 写库」，**提示词（`enrichSystem` / `enrichUser`）一字不改**，常规新闻行为逐字不变（既有测试必须一行不改地全过）。补录路径直接调 `generateFeedEnrichment`，不经过它的读写库逻辑，因此**不会覆盖补录条目里已签名的字段**。

传参约定：
- `title`：抓到的文章自身标题；只有搜索素材时用 owner 那句话。
- `excerpt`：合并后的素材正文（含分档前缀），按既有口径 `slice(0, 4000)`。
- `sourceCompany`：主素材的 publisher。
- `lang: 'zh'`，`kind: 'blog'`。

生成结果的用法：`title_zh` → 候选标题；`ai_summary_zh` → 候选摘要；`excerpt_zh` → 写进 `extra.excerpt_zh`（渲染的 `intro` 用它，卡片图与小红书正文因此也会变厚）；`ai_category` 一并落库。

## 4. 时间预算与进度可见（需求第 5 点）

总上限 **120s**，分段：抓正文 30s、分析拟检索词 30s、搜索 45s、生成 30s。超总预算立即走兜底入池，不得挂住。

线索状态新增可见阶段，页面卡片实时显示（复用既有轮询）：

| 状态 | 卡片文案 |
|---|---|
| submitted | 已提交，排队中 |
| fetching_source | 正在抓取你给的链接正文 |
| analyzing | 正在读懂这是什么新闻 |
| searching | 正在检索相关报道 |
| drafting | 正在生成标题与口播词 |
| recommended / needs_review | 已加入候选池 |
| 失败 | 明确写出卡在哪一步、什么原因（不再是笼统的「处理失败」） |

## 5. 卡片的素材提示三态

| 情况 | 卡片提示 |
|---|---|
| 取到 A/B 档素材 | 正常，标注主素材来源 |
| 只取到 C 档（推文） | 「素材来自 X 博主发文，非公开报道；口播会注明是博主发文」 |
| 什么都没取到 | 「未取到任何公开素材，标题与口播只能依据你写的这句话」 |

## 6. 页面只保留一个提交动作

移除并列的两个按钮，只留「提交并加入候选池」。owner 不需要分辨技术路线。

## 7. 必须修的既有缺陷

1. 搜索的 `Invalid time value`（`date` 为空时抛异常）。
2. 搜索预算 4s/12s → 放宽到与实测相符（单家 45s，总 60s）。
3. `/v1/plain-text` 支持 `url` 与 `query` 同时传（已实现，验证保持）。

## 8. 不可动的边界

- 入池不被取材/生成阻塞或连坐失败。
- 不碰正式新闻门绑定的列（`title`/`content`/`content_translated`/`author`/`url`/`published_at`/`extra.event_fingerprint`）——注意本规格里生成的 title/summary 是**在签名之前**就确定的，所以是写进签名投影，不是事后改写。
- **D1 单语句绑参上限 100**（9/4 事故）：任何新 SQL 不得按集合条数展开绑定。
- 提示词 `enrichSystem` / `enrichUser` 一字不改。

## 9. 验收标准

1. 给一个真实境外文章链接 → 候选标题与摘要来自文章正文，质量与当日其他条目相当（人工比对同批次候选）。
2. 给一个微信公众号链接 → 同上。
3. 只给一句中文线索、不给链接 → 搜索召回真实报道并据此生成。
4. 给一个普通博主的 X 链接 → 入池，口播素材注明「博主发文」。
5. 给一个官方账号 X 链接 → 入池，标注第一方公告。
6. 断网/搜索全挂的模拟 → 仍入池，卡片标明只能依据那句话。
7. 生成后连续两次 sanitize `changed:false`，正式新闻门 `ALLOW_VERIFIED_MANUAL`。
8. 全量测试与 tsc 全绿；常规新闻既有测试一行不改。
