01 执行摘要

一句话：对 Google / Bing / 国际 AI 引擎，ai-feeds.com 当前 Cloudflare 配置已经友好，瓶颈是 SPA 没有 SSR；对中国市场，门槛不在搜索算法，而在「ai-feeds.com 这个未备案域名能否被境内 ISP 稳定访问」。

核心判断

  1. Cloudflare 这一侧不需要再调。 verified bot 体系默认放行 Googlebot / Bingbot / Baiduspider 等所有搜索引擎， ai_bots_protection 也是 disabled，GPTBot / ClaudeBot / PerplexityBot 都能进。 数据印证：24h 内 AI bot 抓取约 206 次（ChatGPT-User 119 / PerplexityBot 44 / GPTBot 22 / ClaudeBot 19）。
  2. AI bot 已经分裂成训练 / 检索 / 用户 fetch 三类，不能用一个开关一刀切。 屏蔽 GPTBot（训练）不影响 ChatGPT search 引用——后者走 OAI-SearchBot； 屏蔽 OAI-SearchBot 才会从 ChatGPT 答案中消失。详见 §03。
  3. OpenAI 与 Anthropic 在「用户触发的 fetch 是否守 robots.txt」上立场分裂。 OpenAI 2025-12-09 修订文档：ChatGPT-User 不再保证遵守 robots.txt，论据是"代理用户行为相当于用户用浏览器"； Anthropic 明确说三个 bot（含 Claude-User）都遵守。 Meta-ExternalFetcher 与 Perplexity-User 与 OpenAI 同立场。
  4. Cloudflare 在 2025-08 公开取消 Perplexity 的 verified bot 资格。 取证：Cloudflare 用全新域名 + 明确 disallow PerplexityBot 的 robots.txt 设陷阱，Perplexity 仍能给出准确回答， 经溯源发现其使用伪装成 macOS Chrome 的通用 UA、在官方 IP 段之外的 ASN 间轮换。 启示：「AI 厂商声明遵守 robots」和「实际遵守」是两件事——这一逻辑同样适用于国内的 Bytespider。
  5. 国内 AI 平台几乎没有可在 robots.txt 中定向控制的训练 bot。 只有 3 家公开了独立 UA：字节 Bytespider、百度 Baiduspider（搜索 + AI 共用）、华为 PetalBot。 阿里 Qwen、腾讯混元、Kimi、智谱、DeepSeek、MiniMax、商汤、讯飞均未公开训练专用 UA， 数据通道走母公司搜索索引、Common Crawl 或私下抓取——robots.txt 对它们无效。
  6. Bytespider 是国内 AI 爬虫流量主力，但不严格守 robots.txt。 HAProxy 实测它占其 AI 爬虫流量约 90%、速度为 GPTBot 的 25 倍； Cloudflare 2025 评估把它列在合规度末位。要拦它得在 WAF 层做行为指纹，写 robots 不够。
  7. 「百度不收录未备案站」是软强制，不是政策禁令。 百度官方文档没有这条规定，但 (a) 2023-11-30 后 sitemap / 快速收录权限收归 VIP，VIP 准入硬性包含 ICP 备案； (b) 境内 ISP 对解析到大陆 IP 的未备案站点在 80/443 端口拦截，Baiduspider 从大陆节点连不上。 结论：技术访问层的硬门槛，不是算法降权。
  8. ai-feeds 的 SPA 是面向所有非 Google 引擎与所有 AI bot 的结构性短板。 Vercel 2025-12 实测：GPTBot / ChatGPT-User / ClaudeBot / PerplexityBot 等主流 AI 爬虫全部不渲染 JS。 Bingbot 半渲染、YandexBot 默认不渲染、Baiduspider 渲染频次远低于普通抓取、Naver / Seznam / Mojeek 完全不渲染。 只有 Googlebot 是 evergreen Chromium 全量渲染。 当前 dashboard 初始 HTML 几乎只有 <div id="root">——除了 Googlebot 之外，所有引擎与 AI bot 看到的都是空壳。
  9. IndexNow 是 Bing / Yandex / Seznam / Naver 的统一推送协议，但 Google 长期拒绝接入。 官方理由：已有 Caffeine + Indexing API、AI / spam 滥用风险、协议由 Microsoft / Yandex 主导。 短期不会变。协议本身没有"撤销 push"语义，错推私密 URL 只能走各 webmaster console 的 URL removal。
  10. Cloudflare 在 2025-07-01「Content Independence Day」之后，新域名默认 block AI crawler。 到 2025-12 已有约 2.5M+ 站点启用 CF managed AI block，覆盖约 20% 公网。 OpenAI 配合最规矩，Pay-per-crawl 仍处私有 beta。详见 §09。

体检结论
  1. Cloudflare 配置不阻碍 SEO 或 GEO，allow-verified-search-engines 是有意识为搜索引擎留的绿灯。
  2. SEO 缺位的成因不在 Cloudflare 这一侧——主站 24h 0 次 Googlebot 抓取意味着没提交 sitemap、没外链、SPA 没 SSR。
  3. GEO 是意外的好结果：完全没做优化，AI bot 已自然占据 verified bot 流量的 95%+。但在 SPA 不渲染的前提下，AI 抓到的内容主体是空壳。
  4. 中国流量尚未真正开始。CN 24h 仅 677 次（含开发自测），后续要做需先解决 .com 未备案 + 境内 ISP 拦截这两个上游问题。

03 Bot 三类法：训练 / 检索 / 用户 fetch

三类 bot 的语义、屏蔽后果、流量回流方式各不相同。「想被 AI 引用但不想被训练」= 禁训练 bot · 放检索 bot · 放用户 fetch bot。

维度 训练 bot 检索 bot 用户 fetch bot
用途 把内容写进模型权重 维护实时检索索引（类比 Googlebot 之于 Google） 用户当下提问触发，去抓一个具体 URL
触发方式 厂商批量自动爬 厂商批量自动爬 用户驱动，单次或少量请求
典型 UA GPTBot, ClaudeBot, Google-Extended (token), Applebot-Extended (token), Meta-ExternalAgent, Bytespider, CCBot, cohere-ai OAI-SearchBot, Claude-SearchBot, PerplexityBot, MistralAI-Index, Applebot, Googlebot, Bingbot ChatGPT-User, Claude-User, Perplexity-User, MistralAI-User, Meta-ExternalFetcher, Amzn-User
抓取频率 几天到几周一次大批量 每天到每小时持续刷新 用户驱动，无规律
遵守 robots.txt 主流厂商都遵守，Bytespider 与 DeepSeek 例外 主流厂商都遵守 立场分裂：Anthropic 守；OpenAI、Perplexity、Meta 明确"may bypass"
Block 后效果 未来训练不再纳入；已训练数据无法移除 从 AI 答案与搜索结果中消失 用户当场提问无法 fetch（OpenAI 例外，绕过 block 直接抓）
是否带流量回到原站 否（纯下载） 间接：被引用时带 referrer 是：被引用时直接附链接
典型策略 "不想被训练" → Disallow "想被 AI 引用获得曝光" → Allow "用户问到我希望能查到" → Allow

写 robots 时容易忽略的 6 个细节
  1. ChatGPT-User 自 2025-12-09 起不保证遵守 robots——你写 Disallow 它也可能照抓。
  2. Meta-ExternalAgent 训练 + 索引合一，无法只 block 训练。
  3. Google-Extended 不是独立爬虫，只是 robots token，控制 Googlebot 抓的内容是否进入 Gemini / Vertex 训练；不影响 Google 搜索排名。
  4. Applebot-Extended 同理，只控制 Applebot 抓到内容的"训练使用权"。
  5. Bytespider 名义上守 robots，社区实测在 list 形式 robots 中会忽略——单独写 block section 才有效。
  6. DeepSeek 没有公开 UA，robots.txt 完全无法控制，只能在 WAF 层做行为指纹。

4 个常见疑问

A. IndexNow 在 2026 是什么状况？

答：Bing / Yandex / Seznam / Naver / Yep（Ahrefs）/ Internet Archive / Amazonbot 已接入； Google 长期拒绝接入，短期不会变。任何一方接收 push 后会广播到所有其他 endpoint。

依据：Google 官方理由：(1) 已有 Caffeine + Indexing API 自有体系；(2) AI / spam 滥用风险； (3) crawl budget 标准要按 Google 自己的；(4) 协议由 Microsoft / Yandex 主导。

容易忽略：协议本身没有"撤销 push"语义。如果错推了私密 URL，urlList 里给 deleted 也只是触发 re-crawl 让引擎自己确认 404， 不是强制 deindex。唯一兜底是 webmaster console 的 URL removal 工具。Bing 单批最多 10000 URL。

B. Google 的 AI Overviews / SGE 对 Googlebot 有特殊政策吗？

答：没有，完全复用现有 Googlebot 索引，没有独立 indexing UA。

依据：官方文档 developers.google.com/search/docs/appearance/ai-features 明确说 AI Overviews / AI Mode 沿用 Search 的索引和 ranking； nosnippet、max-snippet、data-nosnippet 等 preview controls 同时作用于 AI Overviews 和传统精选片段，证明是同一套基础设施。

容易忽略：Google-Extended 不是独立爬虫，只是 robots token。它只控制 Googlebot 已抓内容是否进入 Gemini / Vertex 训练， 与 Search 索引和 AI Overviews 引用无关。2025-12 Search Engine Land 报道 Google 在讨论给 AI Overviews 单独加 opt-out 控件，但截至 2026-05 还没发布。

C. DuckDuckGo 的索引来源 2026 还是 Bing 吗？

答：是。主要靠 Bing，自家 DuckDuckBot 小规模爬取 + 400+ 第三方源做合成。

依据：(1) DuckDuckGo Help Pages 自述 "links and images... we largely source from Bing"； (2) 2024 Bing API 中断时 DuckDuckGo SERP 短暂停摆，证实 Bing 是主体； (3) DuckAssistBot 只在用户触发 DuckAssist 时按需检索 Wikipedia / Britannica 等，不重建索引。

对站长意义：优化 Bing 约等于优化 DuckDuckGo。

5 个常见疑问

A. Block 一个 AI bot 之后究竟会怎样？以 GPTBot 为例

(a) 网站会从 ChatGPT search 结果中消失吗？不会。GPTBot（训练）与 OAI-SearchBot（检索）独立控制。 OpenAI 在 2025 文档中说："如果你两个都允许，我们可能用一次抓取数据用于两个用途，避免重复抓取。" block GPTBot 不影响 ChatGPT search 可见性；要让 ChatGPT 答案不再引用你，需要 disallow OAI-SearchBot。

(b) 之前训练已纳入的内容还会被引用吗？会。一旦数据进入训练好的模型权重就无法移除。 AI 厂商的训练 cycle 通常 12-24 个月才一次，已纳入的内容会一直留到下一代模型替换它。

(c) ChatGPT-User 是否绕过 robots？会，从 2025-12-09 起。 OpenAI 修改文档，将合规承诺仅限于 OAI-SearchBot 与 GPTBot，明确 ChatGPT-User 不再保证遵守 robots.txt。 论据：用户主动让 ChatGPT 访问某 URL 时，OpenAI 视其为代理用户行为。 Anthropic 立场相反——三个 bot（含 Claude-User）都遵守。

B. Cloudflare 与 Perplexity 的抓取冲突始末
  • 2024 年中：Wired / Forbes 揭露 Perplexity 抓取被 disallow 的网站（包括 Forbes、Wired 自己），用隐藏 UA + headless 浏览器
  • 2025-07-01：Cloudflare "Content Independence Day"——所有新域名默认 block AI crawler，pay-per-crawl 私有 beta 上线
  • 2025-08-04：Cloudflare 发布技术 blog 公开取证
  • CF CEO Matthew Prince 在 X 上：把 Perplexity 类比成"北朝鲜黑客"

取证内容：(1) Cloudflare 创建从未被任何 bot 抓过的全新域名，写明 disallow PerplexityBot； (2) 向 Perplexity 提问该域名内容；(3) Perplexity 仍能给出准确回答； (4) 溯源发现 Perplexity 用伪装成 macOS Chrome 的通用 UA，使用未在其官方 IP 段内的 IP，多个 ASN 之间轮换； (5) 规模：每天数十万域名、数百万请求。

结局（2026-05）：Cloudflare 取消 Perplexity 的 verified bot 身份，推出 ML + 网络信号指纹识别 stealth crawler。 Perplexity CEO 反驳称这是"代理用户行为"。 技术圈部分人支持 Perplexity 立场——agent 代理用户该不该受 robots 约束确有争议。

E. AI 引用之后能不能给原站带 referrer 流量？

能带，但比想象中少。ChatGPT、Perplexity 等 AI 答案中的链接点击会带 referrer 回原站，但很大一部分以"Direct"出现： (1) ChatGPT 免费用户 / 移动 app 不发 Referer header； (2) 部分 AI 工具（如 Brave AI summarizer）剥离 referrer； (3) GA4 默认把 ChatGPT 等流量归到通用 "Referral" 桶里，混在普通推荐流量中。

已知 referrer 来源域：chatgpt.com · chat.openai.com · perplexity.ai · gemini.google.com · claude.ai · copilot.microsoft.com · chat.mistral.ai · grok.x.com · you.com · pi.ai · phind.com · huggingface.co。 OpenAI 在某些场景会主动追加 utm_source=chatgpt.com。

典型量级（2026 上半年公开数据）：AI 推荐流量约占总流量 0.2%-2%（行业差异大），但每年增长 5-15 倍。 Cloudflare Radar 公开 crawl-to-referral 比率：OpenAI 1750:1（每抓 1750 页只送回 1 次访问），Anthropic 比率更糟。 意思是：被抓不等于被引，被引也不等于带流量回来。

追踪手段（GA4）：创建 Custom Channel Group → regex 匹配 AI 域名 → 排序到 Referral 之前 → 看 Source / Landing page 维度。

08 ICP 备案专题：流言对照事实

"百度对未备案站不收录"是软强制，不是政策禁令。政策上无该规定，但 (1) 境内 ISP 在 80/443 端口拦截未备案的境内 IP；(2) 百度 sitemap / 快速收录 VIP 准入硬条件含 ICP 备案。实质降权，不是算法降权。Google / Bing 完全不看备案。

ICP 备案规则速查（2026 最新）

法律依据《互联网信息服务管理办法》（国务院令第 292 号）+ 工信部 2017 年域名实名认证全面实施令 + 2024 年《生成式人工智能服务管理暂行办法》
必须备案服务器在中国大陆境内、面向公众提供 Web / APP / 小程序服务的所有网站
不用备案服务器在中国境外（含香港 / 澳门 / 台湾）、个人内网、政府指定专用网络、纯工具类小程序
个人备案身份证 + 手持身份证照片 + 域名实名 + 网站不得用于商业（同一身份证大多省份限 5 个网站）
企业备案营业执照副本 + 法人身份证 + 网站负责人身份证 + 服务器协议 + 公章
顶级域要求 可备 .com / .cn / .net / .org / .com.cn / .top
不可备 .cc / .ai / .io / .xyz / .me / .blog / .pub 等大量后缀（工信部 2018 起未批复）
特殊 .中国 域名需国家级单位
主体 vs 网站主体 = 备案的法律实体；网站 = 主体下的具体域名。一个主体可挂多个网站，更换接入服务商需"接入备案"
公安备案ICP 备案成功 30 日内必须完成（公网安备号），独立于 ICP 备案
2025-2026 新规(1) 双重核验（人脸 + 实地）；(2) AI 类网站需提供《AI 功能说明函》；(3) UGC 类需说明内容审核机制；(4) 个人备案企业站点 2026-06-30 前必须改主体；(5) 违规罚款 5000-10 万元，3 年不得再申请
审核时长接入商初审 1-2 工作日 + 工信部短信核验 + 管局终审 5-20 工作日，总计 1-22 个工作日
底部展示强制要求展示备案号，必须链接到工信部备案查询平台

4 个备案侧关键问题

D. 备案与搜索引擎收录的真实关系
  1. 百度：官方未明文规定"未备案不收录"。但 2023-11-30 后 sitemap 与快速收录权限收归 VIP，准入硬性 = ICP 备案 + 实名 + 运营满 1 年 + 日均点击 ≥ 10000。境内 ISP 在 80/443 端口拦截未备案的境内 IP——爬虫连页面都打不开。
  2. 境外服务器 + 未备案的实测：可以被百度收录，但前提是百度爬虫能访问网站。一篇外贸独立站 SEO 实战指南总结："中国市场必须本地服务器 + ICP 备案 + 结构化"。
  3. Google / Bing：完全不看 ICP 备案。境外搜索引擎只看：服务器响应速度、内容质量、外链权威性、HTTPS、移动端适配。
  4. 2024-2026 政策只增不减：工信部"清朗行动"专项核查 2025Q3 已关停 2 万+ 不合规站点。新规要求愈发严格。
E. 反例：境外服务器 + 未备案 + 百度收录良好的实战案例

能找到的案例极少。普遍情况是境外服务器在国内访问速度慢（300+ ms 延迟、间歇丢包）+ IP 被境内 ISP 周期性封锁 → 百度爬虫即便能爬，索引时效性也大幅落后。

技术博客实战经验显示：靠每日 API 主动提交（每天 10 条限额）勉强维持收录，被动收录基本无望。 所以"境外 + 未备案 + 百度自然收录"这条路理论上可行、实践上极小流量。

F. ICP 备案与 CDN 的细节
  1. Cloudflare Free：全球节点中没有中国大陆节点，"中国境内访问"路由到香港 / 新加坡 / 日本 / 韩国就近节点。延迟 100-300 ms，受跨境带宽和 GFW 影响。
  2. Cloudflare 中国合作版（百度云 / 京东云）：强制要求 ICP 备案。仅企业级合同，免费版无此选项。
  3. 阿里云 / 腾讯云 / 华为云 / 京东云 CDN：所有境内 CDN 都强制备案。"域名解析指向中国内地服务器需备案；指向香港 / 海外不需要"。
  4. 备案号必须显示在网站底部：工信部强制要求，必须链接到备案查询平台。AI 平台索引时未发现"因没显示备案号而降权"的算法依据，但工信部"清朗行动"会因未展示备案号责令整改，长期不改可能注销备案 → 进入 ISP 拦截黑名单。
  5. 合法绕过方案：境外 CDN（Cloudflare Free 全球网络）+ 境外源站，国内访问走最近的境外节点（如香港）。延迟相比境内 CDN 高 5-10 倍，但完全无需备案。
  6. 混合方案：DNS 智能解析做"境内 / 境外分流"——境内走腾讯云 CDN（需备案），境外走 Cloudflare（无需备案）。
G. 境外公司 / 个人想做中国市场 SEO 的合规路径
路径合规效果天花板
找国内主体代为备案（最常见）是完整中国 SEO / GEO 能力，可用境内 CDN，百度 / 360 / 搜狗 / 夸克全收录正常
自己在中国设立子公司或代表处后备案是同上，加上完整运营自主权（成本高）
不备案 + 境外服务器（香港 / AWS HK）合规百度受 ISP 拦截影响，访问速度差；Google / Bing 收录正常
不备案 + Cloudflare 海外网络合规同上，体验劣于香港直连源站
不备案 + 国内非法 CDN（伪装绕过）不合规短期能用，工信部抽查随时下线
不备案，专做 AI 搜索 / GEO 投放边缘主要受内容质量 + 权威平台分发影响；备案不是直接因素

核心结论：面向中国市场的 SEO 天花板在「百度爬虫能否稳定访问到你的页面 + 用户访问体验」。 备案不是法律唯一约束，但它是技术访问性的实质门槛。

ai-feeds 的特殊场景

项目当前架构：ai-feeds.com（未备案，CF Free 海外节点）是主部署； ai-feeds.cc（已备案主体「科赞源信」、网页展示「AI源信」）是国内品牌域名，但暂未启用为主站。

意味着：面向中国市场的 SEO 还没有合法的技术路径，必须做两个决策之一： (a) 启用 .cc 域名作为国内主站 + 境内 CDN / 源站（合规路径）； (b) 维持 .com 主站不备案 + 接受百度长尾天花板（仅靠 Google / Bing / Yandex + AI 引擎）。

10 JS 渲染能力对比

只有 Googlebot 是真正全量 evergreen Chromium 渲染。主流 AI 爬虫全部不渲染 JS（Vercel 2025-12 实测）。任何想被 Google 之外的引擎或 AI 可靠索引的项目，SSR / SSG 是硬要求。

引擎 / Bot 现代 SPA（Vue / React） 渲染机制 实测建议
Googlebot 能 evergreen Chromium，WRS 二阶段：先抓 HTML → 排队渲染 → 索引 仍建议 SSR / SSG，渲染队列有延迟，cache-busting 参数会吃 crawl budget
Bingbot 半能 有渲染但能力弱于 Googlebot；文档明确 rich media 可能漏抓导航 必须 SSR + 给 down-level HTML 兜底
YandexBot 半能（β） Webmaster 控制台手动开 "Recommend rendering" 才会强制执行 默认认为不渲染；SSR 是最稳路径
DuckDuckBot / DuckAssistBot 基本不能 继承 Bing 限制 + 自身 RAG 流不渲染 同 Bing：必须 SSR
Brave Search bot 能 爬取阶段处理 JS（API 不暴露 raw HTML） 一般 SSR 就够
Yeti（Naver） 不能 文档反对 React / Vue 重 JS 必须 SSR / 静态 HTML，否则等于不被索引
SeznamBot 不能 不渲染 必须 SSR / 预渲染

360Spider / Sogou / YisouSpider 弱 未明确公布，社区反馈对 SPA 友好度低 必须 SSR / 静态 HTML

ai-feeds 现状对照

Dashboard 是 React + Vite 纯 SPA，初始 HTML 几乎只有 <div id="root"></div>。 4 个内容源（X / GH / PH / ClawHub）的 item 全部靠 client-side fetch /api/items 才填出来。

意味着：除了 Googlebot 能勉强渲染（且二阶段延迟），其他搜索引擎（含 Bingbot 半能）和所有 AI 爬虫看到的都是空白页。 24h GEO 数据能跑出 200+ AI bot 抓取的唯一原因是——这些 AI bot 即使看到空白也照样抓了， 但抓到的内容主体是空，引用质量为零。

11 矛盾点与模糊点

这些是调研中没有得到一致答案的地方。诚实标注，避免后续做计划时基于错误前提。

  1. 「百度对未备案站不收录」是流言还是事实？百度官方文档从未直接说"未备案不收录"，但 VIP 体系硬条件就是 ICP 备案。结论取决于"如何定义不收录"：完全 0 收录 = 流言；显著降权且收录不稳定 = 事实。本调研采用后者。
  2. 360 与"必须备案才收录"。多数 SEO 文章说"360 基本只认备案域名"，官方文档无明示——这是社区共识与政策硬规定的差距。
  3. Bytespider 是否遵守 robots.txt。CrawlerCheck 标注 "Respects robots.txt: Yes"，但 ai-robots-txt 开源项目、Servebolt、HAProxy 多次报告它在 list 形式 robots 中会忽略。实际操作建议视作"半遵守"，单独写 block section 才有效。
  4. 国内 AI 爬虫 UA 缺乏公开信息。8 家中国主流厂商未公开训练专用爬虫 UA，无法确认它们的训练数据完全来自公开数据集还是有私下抓取。Defense News 2026-04 评论文章指出，由于 GFW 限制，中国 AI 训练数据被"修剪" + 大量 AI 生成内容回流（model collapse），但这是西方视角，国内厂商未公开回应。
  5. PetalBot 归属类别。Cloudflare 把它归为 "AI Crawler"，部分中文资料把它归为传统搜索爬虫。两种说法都对——PetalBot 既支持 Petal Search，也用于盘古大模型训练。
  6. DeepSeek 自爬规模成谜。DeepSeek 公开技术报告（V3 / R1）只披露训练数据量（14.8T tokens），未披露数据采集方式。是否大量自爬未知；其联网搜索调用第三方 API 而非自建索引。
  7. 「备案号未展示导致 AI 平台降权」无算法证据。所有公开材料都只说工信部要求展示备案号，没有任何 AI 平台明文将备案号作为内容质量信号。但内容投放到无备案站点的 AI 收录率显著低（5-15%），这是平台权威度的间接惩罚，不是算法对备案号的直接判断。
  8. Bingbot IP JSON 文件维护频率。WebFetch 拉到的 JSON 缓存版本含 28 个 ipv4Prefix，但 Bing 实际持续维护。生产使用必须每天拉一次以获取增量，不能依赖一次性快照。
  9. DuckDuckBot 自身爬取规模。DDG 长期描述模糊。"超过 400 个源"是市场宣传话术。社区共识自家 crawler 占比可能不足 5%，但没有 DDG 官方披露的具体数字。
  10. Brave Search 是否真的覆盖 40B 页。Brave 自报数字，但没有第三方独立审计。
  11. Yandex 在西方流量的实际重要性。全球搜索市占约 2.5%，但绝大部分集中在俄罗斯及独联体。如果目标受众不含俄语市场，Yandex 优先级实际上很低。
  12. IndexNow 的"撤销 / 重新提交"语义。协议文档没覆盖"提交错了想撤回"。给 deleted URL 不等于强制 deindex，引擎实际上还要重 crawl 验证。如果错提交了私密 URL，唯一兜底是 webmaster console 的 URL removal。
  13. Google AI Mode 是否会启用独立 UA。2025-12 Search Engine Land 报道 Google "正在讨论"为 AI Overviews 加专门控件，但截至 2026-05 没有公开发布。未来 6-12 个月可能有变化。
