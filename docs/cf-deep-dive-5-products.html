1. Queues

持久消息队列：producer 写入 → consumer worker 异步消费 + 自动 retry + DLQ。

核心 API / 用法

Producer 端（worker.toml binding + send）

[[queues.producers]]
binding = "X_PIPELINE"
queue   = "x-pipeline"

# 代码：
await env.X_PIPELINE.send({ tweetId, op: 'classify' });
await env.X_PIPELINE.sendBatch([{body:...},{body:...}]);  // 最多 100 条 / 256KB

Consumer 端（同 worker 或独立 worker）

[[queues.consumers]]
queue                = "x-pipeline"
max_batch_size       = 25       # 1-100, 默认 10
max_batch_timeout    = 5        # seconds, 凑齐 batch 或超时即触发
max_retries          = 3        # 失败 retry 次数
dead_letter_queue    = "x-dlq"  # 重试耗尽进 DLQ

# 代码：
export default {
  async queue(batch, env, ctx) {
    for (const msg of batch.messages) {
      try {
        await processOne(msg.body, env);
        msg.ack();
      } catch (e) {
        msg.retry({ delaySeconds: 30 });
      }
    }
  }
}

价格与配额

免费额度（含在 Workers Paid $5/月里）：1M operations/月（1 op = 1 次 send / receive / delete，所以一条消息端到端 = 3 ops）
超额：$0.40/M operations
消息体大小：≤ 128 KB / 单条；batch ≤ 256 KB
Visibility timeout：30s 默认，最大 12h
消息保留：4 天（未消费消息 4 天后丢弃）
Concurrency：consumer 自动 scale 1-100 并发实例

实际成本估算：你当前每天约 5000 推文流过 pipeline，假设每条经历 4 个 op（fetch/classify/translate/refresh），= 20k ops/天 = 600k ops/月，完全在免费额度内。

✅ 推荐：分阶段切 X / GH pipeline 到 Queue（保留 refresh-tiered + 同步交互）

第一刀（半天）：把 fill-translations 改 Queue，最痛点（DeepSeek 慢 + 偶发 429）。第二刀（1 天）：classify + ingest 整条链 push 到 Queue。第三刀（1 天）：GitHub 4 模式整条链。

收益：(1) cron 不再抢占 slot，删掉 enrich.ts / index.ts 中的 preempt 抢占逻辑；(2) 单条失败不阻塞别的；(3) consumer 自动 scale，吞吐天花板从「单 cron 串行」变「100 并发」；(4) 失败重试 / DLQ 白送，比手写 attempts 列简单。

成本：~3 天工时 + 学习成本（首次接触 CF Queues），月运行成本 0（在免费额度内）。

风险：消息无序（多 consumer 并发），但你 pipeline 业务上没强顺序要求（每条独立处理）。

2. Workflows

持久执行引擎：每个 step 自动持久化 + 失败重试 + 可 sleep 数天数月，类比 AWS Step Functions 但跟 Worker 同源。

核心 API / 用法

定义 Workflow class（一个 Workflow = 一个完整业务流程）

import { WorkflowEntrypoint } from 'cloudflare:workers';

export class TweetIngestWorkflow extends WorkflowEntrypoint {
  async run(event, step) {
    const tweet = await step.do('fetch-from-sb', async () => {
      return await fetchFromScrapeBadger(event.payload.list_id);
    });

    const isAi = await step.do(
      'classify',
      { retries: { limit: 3, delay: '10 second', backoff: 'exponential' } },
      async () => llmJudgeRelevant(tweet, this.env.DEEPSEEK_API_KEY)
    );

    if (!isAi) return { skipped: true };

    const translated = await step.do('translate', () => translateBatch([tweet]));

    await step.sleep('cooldown', '30 minutes');  // 等 30min 再补 quote / metrics

    const enriched = await step.do('enrich-syndication', () => fetchSyndication(tweet.id));

    await step.do('save-to-d1', () => saveToD1(this.env.DB, { tweet, translated, enriched }));

    return { ok: true };
  }
}

触发实例（worker handler 里）

const instance = await env.TWEET_WORKFLOW.create({
  id: tweet.id,           // 业务幂等 key
  params: { tweet_id: tweet.id, list_id: '...' },
});
// 实例自动开始执行；查状态：
const status = await instance.status();

价格与配额

免费额度（含在 Workers Paid $5/月里）：
• 100k workflow steps / 月（每个 step.do / step.sleep 算 1 step）
• 不限并发实例数（单实例最长存活 1 年）
超额：$0.30 per 1k step invocations + Workers CPU time 按 worker 标准计
State 持久化：自动用 CF Durable Object 后端，不收额外存储费
Step 失败 retry：内置指数退避，参数化 limit + delay

每天 5000 推文 × 4 step (fetch+classify+translate+save) = 20k step/天 = 600k step/月，超出免费额度 ~6 倍。需要 ~$150/月（500k overage × $0.30）。这是切之前必算清楚的账。

维度QueueWorkflow

⚠️ 部分推荐：只切 GitHub 4 模式 + Longform 链，X 主链留 Queue 更划算

不切的部分：X 主 ingest pipeline 切 Workflow 月成本 ~$150（按 600k step 算），相比 Queue（~免费）不划算。X 量大的部分（5000/天）走 Queue，量小的（GH 50/天 + longform 100/天）才适合 Workflow。

推荐切的：(1) GitHub 完整链（fetch → enrich → translate → r2-migrate），50 个 repo/天 × 4 step = 6k step/月，免费额度内；(2) Longform 链（探测 + 抓全文 + 翻译），100/天 × 3 step = 9k step/月，免费额度内。两个加起来 15k step/月。

核心收益：(1) trace 可视（CF Dashboard 看每个 instance 走到哪步、为啥失败）；(2) retry 内置；(3) 删掉 D1 里 ai_generated/readme_translated/r2_migrated 等状态字段（Workflow 自管 state）。

成本：~2 天迁 GH，~1 天迁 longform。学习曲线比 Queue 略陡（cloudflare:workers SDK + WorkflowEntrypoint）。

3. Images

边缘图片变换 + 存储。两个产品别混：Cloudflare Images（图片托管 + 自动变换 URL）和 Image Resizing（zone-level cdn-cgi/image，对任意源图变换）。

两种产品的差异

维度Cloudflare ImagesImage Resizing (cdn-cgi/image)
定位上传到 CF 当 CDN，URL 自动变换对你 origin 的图做变换 proxy
需要存储吗是（CF Images 内置存储）否（origin 在哪都行）
价格$5/月 100k stored + 1M delivered不分开计费，按 Pro/Business plan 含
Worker 集成有 binding（env.IMAGES.input(...).transform(...)）fetch /cdn-cgi/image/... URL

核心 API / 用法

方式 A：cdn-cgi/image URL（最简单，对你最适合）

原图 URL：
  https://api.ai-feeds.com/r/abc123-screenshot.png

加变换：
  https://api.ai-feeds.com/cdn-cgi/image/width=400,format=auto,quality=80/r/abc123-screenshot.png

参数：width / height / fit (cover/contain/scale-down) / format (auto/webp/avif/jpeg) / quality (1-100)
   / sharpen / blur / dpr / metadata=keep|copyright|none

方式 B：Worker Images binding（程序化调用）

[[images]]
binding = "IMAGES"

const transformed = await env.IMAGES.input(originalImage)
  .transform({ width: 400, format: 'webp', quality: 80 })
  .output();
return transformed.response();

价格与配额

Image Resizing (cdn-cgi/image)：
• Workers Paid plan 含：5000 unique transformations / 月免费（同 URL+参数命中 cache 不再计）
• 超额：$0.50 / 1000 unique transformations
• 关键：cache hit 不收费，所以反复访问同张图同尺寸 = 1 次费

Cloudflare Images（你不需要这个，下面解释）：
• $5/月含 100k 张存储 + 1M 张 delivered
• 适合需要把图片源迁到 CF 的场景，你已有 R2 + Worker /r/ 反代，没必要再迁

估算：dashboard 当前每天 ~1000 PV，每页 ~30 image = 30k req/天。但 cdn-cgi/image 按 unique transformations 算，同图同尺寸 cache hit。假设独立组合 ~500/天 × 30 天 = 15k unique/月，超 5k 免费 → ~$5-10/月。

实施改造点（dashboard）

// dashboard/src/lib/utils.ts 改造 proxyImg:
export function proxyImg(
  url: string | null | undefined,
  opts?: { w?: number; h?: number; q?: number; fit?: 'cover'|'contain' }
): string {
  if (!url) return "";
  // ... 现有解析 ...
  const params = [];
  if (opts?.w) params.push(`width=${opts.w}`);
  if (opts?.h) params.push(`height=${opts.h}`);
  if (opts?.q) params.push(`quality=${opts.q}`);
  params.push('format=auto');  // 自动 webp/avif
  const transform = params.join(',');
  return `${PROXY_BASE}/cdn-cgi/image/${transform}/img?url=${encodeURIComponent(url)}`;
}

// 调用方升级（举例）：
<img src={proxyImg(avatarUrl, { w: 80, q: 80 })} />          // 头像
<img src={proxyImg(media.url, { w: 800, q: 75 })} />          // 卡片图
<img src={proxyImg(media.url, { w: window.innerWidth * 2 })} />  // Lightbox

✅ 推荐做：纯收益（流量 / LCP 双降）

收益：(1) 移动端流量减 60-80%（webp + 精确尺寸）；(2) LCP / 首屏速度显著提升；(3) format=auto 自动 avif → webp → jpeg 兜底，浏览器侧无需改。

成本：(1) 月费 $5-10（按估算 unique 量）；(2) ~半天工时改 dashboard proxyImg() + 调 5-10 个调用方；(3) cdn-cgi/image 不支持加 query 给同一变换不同 URL（参数变了就是新 transformation）— 注意 dashboard 同图同尺寸要稳定。

风险：origin 图（X / R2）必须能从 CF 边缘 fetch（X 已经能了，R2 同 zone 必通）。

4. Web Analytics

真实用户性能 + 流量监控。CF Dashboard 直接配，不需要写代码（或一行 beacon）。

核心特性 / 配置

开启方式（10 分钟）

  • 方式 B（更精准）：用 RUM beacon JS（一行 <script>），可以拿 SPA 路由级数据。复制 dashboard 给的 <script> 加到 index.html。

核心 API / 用法

Workers Logs（CF Dashboard 看）

# wrangler.toml 加：
[observability]
enabled = true                        # 开启 Workers Logs 写入
head_sampling_rate = 1.0              # 1.0 = 全采样, 0.1 = 10% 采样降本

[observability.logs]
invocation_logs = true                # 自动加 request meta（path/status/duration）

# 查询：CF Dashboard → Workers → 你的 worker → Logs tab
# 支持 filter: status, path, region, ray_id, custom field

# 一次性创建 logpush job（CF API or wrangler，下面 API 示例）

  -d '{
    "name": "xlist-worker-logs",
